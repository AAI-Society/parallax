# P01 — A Trust Calculus for Attestation Tiers

LaTeX source for *A Trust Calculus for Attestation Tiers: Computing Residual
Trust and Re-Deriving Verifiability*.

**Status: working draft. The results sections are placeholdered.** Sections
1–4 and 7 (The Problem, What Others Have Built, Writing It Down Precisely,
Why It Terminates, What We Still Don't Know) are written. Section 5 (Does It
Actually Work?) has the generated comparison matrix and prose, with
`% RESULTS PLACEHOLDER` comments marking the three sub-results still to be
wired in. Section 6 (Re-Deriving the Tiers) is a placeholder for an
experiment that has not been run and says so in the text as well as in a
comment.

**Prose style.** Written in the plain, concrete, direct register the
Proof-of-Control paper uses — examples before abstractions, ordinary words
for technical things, explicit statements of what is *not* known or claimed.
Section titles are plain declaratives ("The Problem", "Does It Actually
Work?", "What We Still Don't Know"). If you are editing this, match that
register; do not translate it into the inflated academic voice.

**Numbers come from the tool, not from the keyboard.** Everything the paper
cites is generated by `../scripts/regen-results.sh` into `../results/` and
`\input` from there. `results/comparison-matrix.tex` is a bare `tabular` —
the caption and float live in `main.tex`. CI regenerates `results/` and fails
on a diff, so a figure in the PDF cannot outlive the code that produced it.
**Do not type a number into `main.tex`.**

## Build

```bash
cd paper
tectonic -Z shell-escape main.tex
```

Output: `main.pdf`. Tectonic fetches packages on first run, so the first
build needs a network connection.

Unlike the Proof-of-Control paper, this one does **not** load `minted`. It
has no syntax-highlighted listings, and `minted` requires a `pygmentize`
binary on the build host, which is a dependency worth not having. `listings`
is configured identically in case that changes. The rest of the preamble —
palette, `\aaimark`, the cover-page TikZ block — is copied verbatim from
`ov-poc-standard/paper/main.tex` so the two papers read as one series.

The build is a CI job (`paper` in `.github/workflows/ci.yml`) and is required
to pass.

## Before Submission — Required Steps

1. **Co-author consent.** The draft currently lists one author. Anyone added
   must review the manuscript and consent to authorship in writing before
   submission; the title-page footnote states this. Do not add names from the
   Society's leadership or advisory lists without asking each person.
2. **Citation verification.** Entries in `references.bib` marked `[verify]`
   carry metadata that has not been checked against the primary source:
   `ascent` (proceedings details and page range), `intelTdx` (specification
   revision and date), `pocspec` and `parallaxtool` (public URLs and versions
   at submission time). Confirm each against the primary literature and fill
   in the missing fields. Check the rest too — a bibliography assembled at
   draft time is not a verified one.
3. **Numbers refresh.** Run `./scripts/regen-results.sh` from the repository
   root and rebuild. Every `% RESULTS PLACEHOLDER` in `main.tex` marks a
   place where generated content still has to replace prose, and none of them
   should survive to submission.
4. **Claims audit.** Two statements in the paper are the ones most likely to
   drift into overclaiming as it is edited, and both are currently correct:
   the tool has been run on five deployments, all of which we wrote; and the
   composition rules are not proved sound. If either stops being stated, the
   paper is overclaiming.
5. **arXiv metadata.** Suggested categories: cs.CR (primary), cs.LO, cs.SE.
   License: Apache-2.0, matching the artifact — arXiv accepts Apache-2.0 as a
   submission licence.
