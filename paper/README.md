# P01 — A Trust Calculus for Attestation Tiers

LaTeX source for *A Trust Calculus for Attestation Tiers: Computing Residual
Trust and Re-Deriving Verifiability*.

**Status: working draft. The results sections are placeholdered.** Sections
1–4 and 7 (The Problem, What Others Have Built, Writing It Down Precisely,
Why It Terminates, What We Still Don't Know) are written. Section 5 (Does It
Actually Work?) has the generated comparison matrix and prose; three
sub-results are still to be wired in. Section 6 (Re-Deriving the Tiers) is a
placeholder for an experiment that has not been run.

**Placeholders are visible in the PDF.** `\placeholder{...}` renders a boxed,
coloured note rather than a LaTeX comment, because a comment marking
unfinished content is invisible to everyone who reads the compiled paper —
which is everyone who reviews it. Before submission, `\draftfalse` in the
preamble turns the boxes off; do that only after `grep -c '\\placeholder'
main.tex` returns 0, since with drafts off a surviving placeholder does not
warn, it just vanishes and leaves the surrounding prose reading as a
finished claim.

**Prose style.** Written in the plain, concrete, direct register the
Proof-of-Control paper uses — examples before abstractions, ordinary words
for technical things, explicit statements of what is *not* known or claimed.
Section titles are plain declaratives ("The Problem", "Does It Actually
Work?", "What We Still Don't Know"). If you are editing this, match that
register; do not translate it into the inflated academic voice.

**Numbers in Section 5 come from the tool, not from the keyboard.** Results
are generated by `../scripts/regen-results.sh` into `../results/` and
`\input` from there. `results/comparison-matrix.tex` is a bare `tabular` —
the caption and float live in `main.tex`. The `rust` CI job regenerates
`results/` and fails on a diff, so a figure in the PDF cannot outlive the
code that produced it. (The `paper` job only runs tectonic; it is the `rust`
job that enforces freshness.) **Do not type a result into Section 5 by
hand** — add it to `regen-results.sh`.

Numbers *outside* Section 5 — deployment parameters quoted in Section 1,
the code size, the size of the termination example — are prose, not tool
output, and the abstract's artifact note says so. Do not broaden that note.

**Table 2 is hand-maintained**, and is the paper's contract with
`src/mechanism.rs`. `every_rule_appears_in_the_papers_table` in that file is
a tripwire: it fails if the set of (mechanism, capability, Δ, impact)
4-tuples the code can emit stops matching the table's fourteen rows, and a
compile-time match guard fails if a `MechanismSpec` variant is added. All
four of the table's columns are pinned — an earlier version compared only
mechanism and capability, which left the Δ and impact columns free to drift
from the code with the whole suite green. The test also checks the two
counts the caption asks a reader to believe: ten rows carry an
unconditional `never`, four carry a declared duration. The caption's
remaining claim — that `anchoring`'s settlement assumption is the one row
where `never` is an overridable *default* — is pinned separately by
`anchoring_settlement_without_finality_defaults_to_never`. If any of these
fires, update the table *and* its caption in the same commit.

## Build

```bash
cd paper
tectonic -Z shell-escape main.tex
```

Output: `main.pdf`. Tectonic fetches packages on first run, so the first
build needs a network connection.

Unlike the Proof-of-Control paper, this one does **not** load `minted`. It
has no syntax-highlighted listings, and `minted` requires a `pygmentize`
binary on the build host, which is a dependency worth not having. `listings`
is configured identically in case that changes. The rest of the preamble —
palette, `\aaimark`, the cover-page TikZ block — is copied verbatim from
`ov-poc-standard/paper/main.tex` so the two papers read as one series.

The build is a CI job (`paper` in `.github/workflows/ci.yml`) and is required
to pass.

## Before Submission — Required Steps

1. **Co-author consent.** The draft currently lists one author. Anyone added
   must review the manuscript and consent to authorship in writing before
   submission; the title-page footnote states this. Do not add names from the
   Society's leadership or advisory lists without asking each person.
2. **Citation verification.** Entries in `references.bib` marked `[verify]`
   carry metadata that has not been checked against the primary source:
   `ascent` (proceedings details and page range), `intelTdx` (specification
   revision and date), `pocspec` and `parallaxtool` (public URLs and versions
   at submission time). Confirm each against the primary literature and fill
   in the missing fields. Check the rest too — a bibliography assembled at
   draft time is not a verified one.
3. **Numbers refresh.** Run `./scripts/regen-results.sh` from the repository
   root and rebuild. Then `grep -c '\\placeholder{' main.tex` — every hit is
   generated content that still has to replace prose, and none should survive
   to submission. Only then set `\draftfalse`. This is no longer only a
   checklist item: the `paper` CI job prints the count on every run and
   *fails* the build if `\draftfalse` is set while any placeholder remains,
   which is the dangerous combination — with drafts off a surviving
   placeholder does not warn, it vanishes and leaves the surrounding prose
   reading as a finished claim. It does not fail while the paper is still
   marked `\drafttrue`, because the placeholders are then visible in the
   PDF by design and a permanently red job teaches everyone to ignore it.
4. **Claims audit.** Four statements are the ones most likely to drift into
   overclaiming as the paper is edited, and all four are currently correct:
   (a) the tool has been run on five deployments plus a negative control, all
   of which we wrote; (b) the composition rules are not proved sound; (c) the
   TDX result derives the *content* of Table 1, not the *identities* of the
   five parties, which the deployment file names; and (d) only two unordered
   pairs in Table 3 were actually compared, the other eight ordered pairs
   being N/A. If any of these stops being stated, the paper is overclaiming.
5. **Counts audit.** Three counts in the prose are checkable against the
   repository and will rot: the line count in Section 1, the deployment count
   in Section 5, and the fourteen rows of Table 2 (which the tripwire test
   covers). Re-derive them rather than trusting the draft.
6. **arXiv metadata.** Suggested categories: cs.CR (primary), cs.LO, cs.SE.
   License: Apache-2.0, matching the artifact — arXiv accepts Apache-2.0 as a
   submission licence.
